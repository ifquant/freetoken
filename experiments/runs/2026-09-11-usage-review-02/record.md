# 从使用角度审查与完善：第二轮

日期：2026-09-11。用户要求：加强 Codex 审核后继续派工的闭环、支持一次性任务、允许清理会话；随后明确只需关闭并清理本工具日志。

## 发现与修正

1. 原版 review 和 resume 能组合，但需要二次提供反馈。新增 `revise --evidence-file`，记录 needs_work 后将同一份审核证据发回准确旧会话；已记录 needs_work 后，resume 可直接使用保存的审核意见。自动反馈在工作区变化后拒绝发送，要求新的明确反馈。
2. 原版没有跨尝试上限。新增每任务默认 3 次（含首次、失败、取消），显式 `--max-attempts` 才能延长。skill 明确由 Codex 负责关键判断、失败样例、独立验收，并在同一用户请求内继续普通返工；达到上限后重新判断，不机械循环。
3. 新增 `start --one-shot`：单次派发，保留审核，拒绝续接。CodeBuddy 使用原生 no-session-persistence；dsh 仍可能保留后端历史。
4. 新增 `cleanup [--purge-raw]`：关闭此任务的续接能力，可删除本任务全部原始日志。报告、审核、快照、usage 和结果保留。活跃/未解决任务拒绝清理；不跟随 raw 目录符号链接删除；可重复执行，删除目录记录保留。不删除项目文件及后端历史。
5. 原安装把整个仓库链接进 skills，导致参考项目内的其他 skill 被发现。已改为只链接本项目的 SKILL.md 和 scripts/。本地入口及 validator 通过；发现列表刷新需下一次加载。
