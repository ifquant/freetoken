# 可复用派工交付与证据边界

日期：2026-09-11。入口：[README](../README.md)、[SKILL](../SKILL.md)、[实验总表](../experiments/RESULTS.md)。

## 交付决策

默认按一个能独立验收的行为变化派一个工作包，让工人自行调查、实现和自检；Codex 保留范围判断、失败反馈和独立验收。需要先解决关键设计决策时才拆调查轮，相关反馈续接准确的旧会话。独立任务使用两个工作区并行，共用工作区由锁串行化。

依据是本次小样本：CodeBuddy 完整工作包 33.20 秒；三轮拆分在 62.23 秒时因上游 502 未正常交卷。dsh 完整工作包 20.37 秒；三轮拆分 54.28 秒。两项独立任务顺序/并行分别为 CodeBuddy 61.65/25.45 秒、dsh 57.36/26.66 秒。不能据单次运行把 502 归因于粒度，也不能把这些数字推广为稳定加速比例。

这些结果支持先采用简单工作包、按独立性并行的工作方式，尚不支持自动调度算法、缓存优化器或费用预测器。不同后端用了不同模型，不做后端性能排名。

## 已实现的控制

- Git 工作区及任务锁；任务、会话、轮次、控制进程身份与工具事件可查。
- 每轮墙钟预算、主动取消、取消宽限、观察到的子进程清理；启动阶段也检查预算。
- 结果收集与独立 review 分开，错误结果即使退出码为 0 也不会被接收。
- 原会话续接、取消后完成剩余操作；未知状态先 recover，不猜测最近会话、不自动重派。
- 每轮前后文件哈希与修改范围核查；已有修改保留；过期验收拒绝；越界不自动回滚。

实现仅依赖标准库和现有 CLI。没有数据库、后台服务或无人值守定时任务。CLI 阻塞运行，Codex 利用宿主执行句柄等待并按需查状态。

## 适用边界

当前实测为 macOS、CodeBuddy 2.149.0 + deepseek-v4.1-flash、dsh 0.1.5-rc.1 ACP + deepseek-official/deepseek-v4-flash。执行路径可以固定，模型与会话会记录；升级 CLI 后应重新运行小型检查。Linux 未实测，Windows 不支持。

两个复用项目是独立的小型 Python Git 项目，包含函数、CLI、冻结验收和已有脏文件；不是大型生产仓库。并行对照也只覆盖独立项目，未验证存在冲突的分支整合。skill 文件与脚本已本机安装并检查，新任务自动发现尚未现场验收，可显式读取入口。

Dispatch 前须先确认外部会话空闲或已交接，再派工；runner 锁不能覆盖独立启动的会话，不应自动终止它们。

使用完整权限；范围声明、锁与快照不是沙箱。其他工具写入、忽略文件、子模块内部、工作区外文件、未被观察到的脱离进程不受完整保护。停止检查只覆盖本次记录的进程身份，不能保证任意外部副作用不存在。

会话续接依赖本机后端历史仍存在；删除历史、跨机器迁移历史、长期离线恢复未测。没有自动推送、部署、外部通信或无限故障重试。预算限定一次尝试的时间，到期后另需停止/清理宽限；没有可归属的货币或订阅额度硬限。

## 用量结论

保留供应商返回的 usage 原值；CodeBuddy 的 usage 与 modelUsage 口径并不一致，部分字段有会话累计特征，不能跨轮简单求和。ACP usage_update 也未与账单对齐。报告费用 0 不证明免费。

新会话不等于冷缓存，旧会话不保证缓存命中。未进行供应商缓存失效/命中控制，也未获得每次实验可归属的 Codex 订阅额度，因此不报告缓存节省率、总费用节省或 Codex token 节省。总完成时间、交卷状态、失败轮数及回传字节仅作为本次代理指标，验收程序耗时不包含全部 Codex 思考与阅读。
