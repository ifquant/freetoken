## 初步建议（助手提出，未经用户定案）

将派工规则封装为精简 skill，复用 CLI 执行；先比较 CodeBuddy CLI 与 dsh，保留 sidecar 路线。

skill 与 CLI 是不同层次：前者定义何时派工、任务边界及验收流程，后者负责实际执行。只有实际调用表明确有需要时，才增加启动或结果采集脚本。

CodeBuddy 的现有接口适合先验证完整派工闭环；dsh 的单任务入口简单，但自动续接与状态采集仍需核对；sidecar 提供 Codex harness 内的工人运行方式，同时引入 provider 配置与兼容性维护。

## 候选工作流程

1. Codex 给出目标、范围、必要背景和验收要求。
2. 工人探索与执行，返回结论、改动位置、检查结果和未解决项。
3. Codex 检查关键证据与 diff；返工续接明确的原会话。
4. 并行写入时使用独立 worktree，另行约定整合方式；worktree 不是权限沙箱。

避免 Codex 与工人重复全量阅读，以及将工人的全部日志回灌主会话。
